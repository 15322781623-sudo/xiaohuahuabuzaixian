## ✨ 新功能

### 1. 批量日常爬怪异塔分批并发控制
**需求背景**：一键爬怪异塔功能缺少明确的批次控制机制，采用滑动窗口模式不利于追踪执行进度。

**实现方案**：
- ✅ **分批执行模式**：每批最多 `maxActive` 个账号，本批全部完成后才执行下一批
- ✅ **批次进度日志**：显示"📦 批次 N/M 开始执行 X 个账号"和"✅ 批次 N/M 执行完成"
- ✅ **重试分批控制**：重试流程也采用相同的分批并发模式
- ✅ **Promise.all 并发**：使用 `Promise.all` 并发执行本批所有账号

**技术细节**：
```javascript
// 主执行流程
const maxActive = batchSettings.maxActive || 5;
const totalBatches = Math.ceil(totalTokens / maxActive);

for (let batchIndex = 0; batchIndex < totalBatches; batchIndex++) {
  const batchTokens = selectedTokens.value.slice(
    batchIndex * maxActive, 
    Math.min((batchIndex + 1) * maxActive, totalTokens)
  );
  
  addLog({
    message: `📦 批次 ${batchIndex + 1}/${totalBatches} 开始执行 ${batchTokens.length} 个账号`,
    type: "info",
  });
  
  await Promise.all(batchTokens.map(tokenId => processClimbWeirdTower(tokenId)));
  
  addLog({
    message: `✅ 批次 ${batchIndex + 1}/${totalBatches} 执行完成`,
    type: "success",
  });
}
```

## ⚡ 优化改进

### 1. 爬怪异塔能量刷新策略优化
**优化目标**：减少 API 调用频率，降低服务器压力，提升爬塔稳定性。

**优化方案**：
- ✅ **刷新频率调整**：从每次刷新改为每 8 次刷新一次
- ✅ **智能估算机制**：非刷新周期自动扣除 1 点能量，无需真实数据
- ✅ **功能完整性保留**：每日宝箱检查和领取仍正常工作
- ✅ **容错降级处理**：API 失败时自动降级为估算模式
- ✅ **日志清晰化**：只显示刷新节点，避免信息过载

**性能提升**：
| 指标 | 优化前 | 优化后 | 提升幅度 |
|------|--------|--------|----------|
| API 调用量 | N 次 | N/8 次 | **减少 87.5%** |
| 日志输出 | 每次都有 | 每 8 次显示 | **减少 87.5%** |
| 每日宝箱检查 | 每次都检查 | 每 8 次检查 | **减少 87.5%** |
| 服务器压力 | 高 | 低 | **降低 87.5%** |

**技术实现**：
```javascript
// ✅ 只在每 8 次时获取完整信息（包含能量和任务数据），其他次数估算
if (count % 8 === 0) {
  try {
    const newInfo = await callWithRetry(tokenId, "evotower_getinfo", {}, { retries: 1 });
    currentEnergy = newInfo?.evoTower?.energy || 0;
    
    addLog({
      message: `${token.name} 💡 第${count}次后刷新 - 剩余能量：${currentEnergy}, 总次数：${count}`,
      type: "info",
    });
    
    // ✅ 同时领取每日宝箱（也只在每 8 次时检查）
    const taskClaimMap = newInfo?.evoTower?.taskClaimMap;
    if (taskClaimMap) {
      // ...领取每日任务逻辑...
    }
  } catch (refreshError) {
    // 刷新失败时减少能量估算
    currentEnergy = Math.max(0, currentEnergy - 1);
    addLog({
      message: `${token.name} ⚠️ 刷新能量/任务信息失败，按减少能量估算：${currentEnergy}`,
      type: "warning",
    });
  }
} else {
  // 非刷新周期，按正常消耗估算（不再调用 API）
  currentEnergy = Math.max(0, currentEnergy - 1);
}
```

## 🔧 技术细节

### 1. 批次计算算法

```javascript
const totalBatches = Math.ceil(totalTokens / maxActive);
```

- 使用 `Math.ceil` 确保最后一批即使不满也能执行
- 例如：100 个账号，maxActive=5 → 20 批
- 例如：103 个账号，maxActive=5 → 21 批（20 批满 + 1 批 3 个）

### 2. 批次切分算法

```javascript
const startIdx = batchIndex * maxActive;
const endIdx = Math.min(startIdx + maxActive, totalTokens);
const batchTokens = selectedTokens.value.slice(startIdx, endIdx);
```

- 使用 `slice` 切分账号数组
- `Math.min` 确保最后一批不会越界
- 例如：batchIndex=19, maxActive=5, totalTokens=100
  - startIdx = 95
  - endIdx = Math.min(100, 100) = 100
  - batchTokens = slice(95, 100) → 最后 5 个账号

### 3. 能量估算算法

```javascript
currentEnergy = Math.max(0, currentEnergy - 1);
```

- 每次战斗后扣除 1 点能量
- 使用 `Math.max(0, ...)` 确保能量不为负数
- 在下次刷新时校准真实值

### 4. 容错降级机制

```javascript
catch (refreshError) {
  // 刷新失败时减少能量估算
  currentEnergy = Math.max(0, currentEnergy - 1);
  addLog({
    message: `${token.name} ⚠️ 刷新能量/任务信息失败，按减少能量估算：${currentEnergy}`,
    type: "warning",
  });
}
```

- API 调用失败时自动降级
- 输出警告日志提醒用户
- 确保爬塔流程不中断
